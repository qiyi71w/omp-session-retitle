| --- | --- |
| `bun run check` | 提交前最终复验：类型检查通过，85 pass、1 skip、0 fail，191 个断言。默认跳过的原生烟测单独执行，结果见下一行。 |

固定的分类枚举、来源标签解析和编号数量限制已移除；相应旧契约测试删除。通用格式测试覆盖自定义 `[T#42]`、`PROJ-42` 和分类前缀，验证器不解释这些标签的业务含义。生产通知已改为英文，行为测试不绑定具体语言文案。

## 覆盖行为

**提示词选择：** 项目 `.omp/TITLE_SYSTEM.md` 优先于 agent 目录；都不存在时使用扩展规则；显式 `bundled` 绕过发现；高优先级 `null` 恢复发现；两个自定义规则路径分别相对于声明它们的配置文件解析。手动规则可关闭或替换。选中的文件缺失、空白、过大或不是普通文件时失败关闭。

**标题与来源：** 普通中文/英文标题、自定义分类与 tracker 格式、OMP `<title>` 包装及空标题哨兵；拒绝多行、隐藏/控制字符、超长或损坏包装。编号证据由提示词交给模型判断，本地不提供语义真实性保证。输入 JSON 有预算，保留早期目标和最近纠偏。

**独立调用：** provider/model 和独立 reasoning、关闭推理的真实选项、精确模型匹配、认证与上下文预算检查；认证解析携带主会话 ID，transport sessionId 独立，不共享 Responses 续写或主 prompt。未改变原有模型请求契约。

**状态与撤销：** 旧响应丢弃、cancel/模拟 Esc、provider 忽略 signal、超时、切走再切回、cwd/leaf/新消息变化、busy/queued、外部改名及改回同名；undo 不继承兄弟分支权限；损坏 journal 不复活旧记录；保存期间互斥、失败后条件回滚并保留原 undo。

**真实运行边界：** 原生 RPC 烟测使用临时 HOME/agent/XDG 目录及离线模拟 provider，不加载用户凭据、不调用真实模型；验证 `<title>` 输出被保存为普通标题，以及同一实例重读新项目规则。测试结束终止自己创建的进程并删除临时目录。已有真实 SessionManager 集成覆盖分支投影、元数据不进入模型消息、controller 重建撤销记录和手动标题防止自动覆盖。

## 未实测 / 不承诺

- 已进行下述有限真实模型对照；不代表所有长会话、语言或 provider 的质量。离线烟测另外验证规则传递、输出解析及状态更新。
- 未实测真实 OAuth 多账号、broker/proxy、额度耗尽、refresh 或 failover。认证语义来自 18.1.16 源码及模拟调用参数核查。
- 未手动操作真实 TUI 的 Esc；Windows 原生、macOS、其他 OMP 版本未测试。
- 未验证多个进程同时写同一 session、真实磁盘损坏、掉电、落盘关闭再重开的完整恢复；公开接口没有跨进程 CAS 或事务回滚保证。
- 已验证本地用户级插件链接及自动加载；未执行 npm 发布。未修改 OMP core。

## 真实模型对照：2026-09-11

### 方法

- OMP 18.1.16 原生 RPC 宿主，使用同一已配置的 OpenAI-compatible provider `ccswitch-codex`。比较 `gpt-5.6-luna`、`gpt-5.6-sol` 与当前会话的 `gpt-6-astra`。
- 调用生产 `buildTitleInput → loadRules → generateTitle → validateTitle` 路径。Luna/Sol 使用显式 model 配置；Astra 使用 `model: null`，从宿主当前模型取得标识。保持 `reasoning: off`、`maxOutputTokens: 1024`、`maxInputChars: 24000`、60 秒超时。
- 首轮每模型 6 个相同样本：本项目真实分支的通用标题、同一分支的用户四段规则、英文家庭旅行规划、明确纠偏后跟随 20 条测试/CI 收尾消息、ticket/Issue/新建 PR 区分、纯问候。轮换各样本的模型调用顺序，串行请求。
- 追加同一四段规则样本的无 hint 重复和明确任务对象 hint 对照，每模型 2 次。共 24 次真实模型调用；没有生成失败、格式失败或超时。没有改任何会话标题；结束后 RPC `get_messages` 仍为空。
- 记录完整调用耗时、真实 usage 和候选标题，不收集或输出凭据、请求 headers、原始 provider 错误。临时 benchmark 扩展和包含会话文本的样本不进入发布包。

### 使用建议

- 日常刷新推荐 **Luna + `medium`**。下方扩展验收中，16 次有 15 次优选、1 次可用，耗时中位数 2.63 秒。
- 更重视标题完整性、可以接受较长等待时可选 Luna + `max`；本次为 16/16 优选，中位数 4.46 秒。
- 扩展默认仍是 `model: null`、`reasoning: off`，沿用用户已有的 provider/model；这与推荐配置是两回事，reasoning 不继承主会话设置。
- 输出上限先保持 1024；本次各档位均正常完成。费用同时受历史、规则长度和 provider 计费影响，复用主模型不保证共享缓存或更便宜。

## Luna 各档位验收：2026-09-11

### 方法与判定

在 OMP 18.1.16 原生 RPC 宿主中，使用 `ccswitch-codex / gpt-5.6-luna` 调用扩展的生产标题生成路径。固定 8 个场景，每个场景在 `low / medium / high / xhigh / max` 下各运行两次，共 80 次调用；输出上限 1024 token，超时 60 秒。

| 场景 | 验收重点 |
| --- | --- |
| 本项目真实会话 | 保留 OMP 会话标题扩展及通用化目标 |
| ticket 与新建 PR | 标题来源保留原任务 T#08，不被新建 PR 替换 |
| PR 审查 | 保留 PR#42、登录令牌刷新竞态和 review 工作流 |
| 只排查、不实施 | 支付回调重复执行应归为 triage |
| 英文非代码任务 | 保留三天京都家庭旅行主体，不被 PDF 导出步骤带偏 |
| 纠正后跟随 CI 收尾 | 保留应用多语言设置与切换的实现目标 |
| 纯问候 | 返回无任务结果，保留原标题 |
| 长历史与干扰摘要 | 裁剪后保留 AtlasSearch 文档增量索引，不采纳摘要中的 I#999 |

英文任务、CI 收尾和问候使用扩展内置规则；其余场景使用自定义四段标题规则。这些前缀是验收样本的要求，不是扩展默认格式。

先隐藏 effort 标签，按场景审阅去重后的标题，再映射回各档位。人工分级为：**优选**（对象明确且关键细节完整）、**可用**（任务正确，但遗漏限定或附带次要产物）、**不可用**（错误任务或无关文本污染）。这是小样本主观对照，不是统计显著性结论。

### 档位支持与调用结果

预先探测了所有配置值：该线路的 `off` 实际发送 `low`，所以不作为独立档位重复计数；`minimal` 不受目标模型支持，在发出请求前失败。其余五档发送的 effort 与配置一致。该映射仅代表本次模型和 provider。

80 次调用均正常结束并通过本地格式校验，没有超时或输出截断。格式有效不等于标题可用：`low` 有一次混入无关特殊 token 文本，人工判为不可用。下面的质量数量互斥，每行合计 16 次。

| reasoning | 优选 | 可用 | 不可用 | 耗时中位数 | 输出 token 总计 | 其中推理 token | 每 1000 次无缓存参考费用 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `low` | 13 | 2 | 1 | 2.21 秒 | 709 | 456 | $0.617 |
| `medium` | 15 | 1 | 0 | 2.63 秒 | 973 | 709 | $0.637 |
| `high` | 14 | 2 | 0 | 3.37 秒 | 1817 | 1546 | $0.700 |
| `xhigh` | 14 | 2 | 0 | 3.36 秒 | 2109 | 1835 | $0.722 |
| `max` | 16 | 0 | 0 | 4.46 秒 | 3374 | 3099 | $0.817 |

耗时为端到端调用时间。token 是每档 16 次的总量，输出已包含推理 token。费用沿用上文记录的参考单价（输入 $0.20、输出 $1.20 / 百万 token），将缓存读取按普通输入计价后归一到 1000 次，以排除不同档位偶发缓存命中的影响；不是实际代理账单。

### 质量差异与推荐

- `medium` 唯一的“可用”结果为 `[-][enhancement][implement] OMP 会话标题扩展`：对象正确，但未说明“通用化”目标。其余 15 次达到优选标准。
- `low` 除一次文本污染外，两次旅行标题都附带 PDF 产物；其中一次还遗漏了三天限定。
- `high` 一次省略 AtlasSearch 项目名，一次旅行标题强调 PDF 并遗漏家庭出行限定；`xhigh` 的两次旅行标题都附带 PDF 产物。两档在本组没有表现出优于 `medium` 的质量。
- `max` 本次全部优选，但耗时中位数比 `medium` 多 1.83 秒，推理 token 总量也更高。

**推荐 Luna `medium` 作为日常手动刷新配置**：本组质量接近 `max`，等待时间更短。对标题细节要求更高时可选 `max`；主题有误时先用 `/retitle 补充说明` 明确任务对象。每个场景仅重复两次，结果不能保证其他会话、提示词或线路也有相同表现。
